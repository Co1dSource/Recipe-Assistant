# 阶段 3 游戏验收

以下均为待执行步骤。Codex 未启动 Minecraft；构建和无游戏检查不能代替这些测试。
客户端只保留一份新版 `ctirecipeassistant-0.3.1.jar`。不要复制到服务器。
环境：MC 1.19.2、Forge 43.4.12、Java 17、JEI 11.6.0.1024、AE2 12.9.9。

1. 加入原 CTI 服务器。确认无 Mixin 加载异常，G 打开已验收的配方树，展开、切换和偏好仍正常。
2. 分别从普通 3×3 工作台和 AE2 合成终端打开 JEI“合成”类别，选择一页显示多张配方的分类。每张配方右侧顶部应各有一个 13×13 小按钮，与原填入按钮的横坐标一致，图标和背景一致，配方输入输出未被遮挡。
3. 逐个悬停新增按钮，提示应为“一键合成配方树”。逐个点击，聊天应显示对应目标、类别及配方指纹，并明确“阶段 3，未执行”。相邻按钮不得串配方；背包、工作台和光标物品数量不变。
4. 点击 JEI 原版右下角填入按钮，确认仍执行原有 JEI 行为。该按钮不是本阶段的待执行入口。
5. 从 AE2 样板编码终端打开 JEI。新增按钮提示应为“批量编码配方树样板”；点击后调试提示模式相同。空白样板、假槽、编码输出及背包都不得改变。
6. 从 AE2 样板管理终端（PatternAccessTermMenu）打开 JEI。新增按钮应隐藏，原位置不能点击或弹出新增按钮的提示，不能进入批量编码模式。
7. 从背包 2×2、箱子、普通 AE2 存储终端，以及无父级容器的 JEI 入口打开配方。新增按钮均应隐藏，原位置不能触发操作。反复切换普通 3×3 工作台、编码终端和这些界面，显示条件和提示应实时变化。原版 JEI 按钮保持原有行为。
   普通工作台及 AE2 合成终端中切换到烧炼、高炉、烟熏、营火、切石或机器类别，新增一键合成按钮应隐藏，原位置不能触发操作；切回“合成”后恢复。编码终端仍保留处理配方的样板入口。
8. 更改 GUI 缩放后，检查单配方、多配方、翻页、切换类别及调整窗口尺寸。按钮应分别跟随对应布局；边缘和中心点击与图像一致，不能点击到相邻配方。特别检查高度很小的配方：新增按钮会向上避让原填入按钮。
9. 选择机器多输出/副产物配方。点击新增按钮默认取第一个非空输出槽当前显示的候选；若该槽轮换候选，可等待轮换再点。类别和配方指纹应保持同一配方。上下文 `candidate.outputs()` 保留全部输出，`slotsView` 保留真实所有槽位，没有按物品名重新查询配方。
10. 若存在无输出候选的 JEI 配方，新增按钮应灰显，提示“配方未提供可选目标产物”，点击不分发。普通配方本阶段不做材料库存判断，即使缺料也只记录待执行请求。

本阶段没有自动打开树、填料、合成、编码或传输。运行中的实际布局、Mixin 应用和三类菜单行为以本次游戏验收为准。
